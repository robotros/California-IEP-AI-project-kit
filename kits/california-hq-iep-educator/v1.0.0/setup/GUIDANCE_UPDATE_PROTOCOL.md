# CURRENT GUIDANCE GATE — mandatory operating and maintenance protocol
**REQ-LAW-01 — never claim continuously up-to-date legal guidance from a static attachment.**

## Each substantive educator task / each new compliance claim
1. Identify specific legal issue, student's *nonidentifying* relevant context, rule effective date that matters and school calendar if legally relevant. Ask no student identifiers.
2. Use read-only live tools if available to check relevant **federal** law/IDEA/34 CFR Part 300 from U.S. Department of Education/IDEA or eCFR, and relevant **California** Education Code/Title 5 regulations on Legislature/CDE/official regulation source, plus applicable CDE current guidance. Do not rely on summaries or last week's chat as verification. Federal and state may have different requirements.
3. Display citations and `retrieved_on`, `text_effective_on` when known, `last_verified_snapshot`, `applicability`, and `changes_since_snapshot`: CHANGED / NO_MATERIAL_CHANGE_WITH_COMPARISON / UNDETERMINED. Never write 'no change' without verified previous baseline.
4. Check state/local tension: if SELPA/district approved and supplied, record its version and conflict/uncertainty. Otherwise mark LOCAL NOT VERIFIED, not presumed identical.
5. Binding law/regulation is distinguished from nonbinding guidance and HQ IEPs teaching materials. A new bill can have an upcoming future effective date; don't treat pending provision as currently applicable.
6. If tools missing, site blocked, authority ambiguous, version comparison unsupported, or sources conflicting: print `CURRENT GUIDANCE NOT VERIFIED — legal/compliance conclusions ON HOLD` when actual current legal validity cannot be established. Continue only clearly provisional educational assistance; request qualified authority review and cite what *was* actually checked.
7. If material update found: issue change proposal with section/source, former rule as **verified**, new language/paraphrase, effective date, affected instructions/knowledge/prompts/Skill/templates/adapters/tests, review owner and rollback. Do not silently change kit, send notification, set up automation or publish.

## Suggested owner-driven review cadence (not automated)
At each legally sensitive usage: check current sources. Additionally, an authorized content owner can review official update feeds monthly and before each academic-year launch or after an important CDE/IDEA bulletin. This is a *manual plan*, not evidence that monitoring is running. If separately configured recurring monitoring later, approval and independent review of any changes still apply.
