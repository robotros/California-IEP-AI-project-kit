# IEP Goal Generator — Standards, Sources, Crosswalk and Safeguards

**Edition:** LIGHTWEIGHT. **Knowledge file 2 of 2.** Use alongside the ChatGPT instruction summary, the uploaded full project instructions, and the companion lightweight workflow file.

## Source priority and official verification

- **Federal IEP requirements:** [34 CFR § 300.320](https://www.law.cornell.edu/cfr/text/34/300.320).
- **California IEP content:** [California Education Code § 56345](https://leginfo.legislature.ca.gov/faces/codes_displaySection.xhtml?lawCode=EDC&sectionNum=56345.).
- **Grade-level alignment clarification:** [US Department of Education OSEP 2015 guidance](https://sites.ed.gov/idea/idea-files/osep-dear-colleague-letter-on-free-and-appropriate-public-education-fape/).
- **Official standards:** [California Content Standards](https://www2.cde.ca.gov/cacs/); [California PTK Learning Foundations](https://www.cde.ca.gov/sp/cd/re/psfoundations.asp) for appropriate early-learning contexts.
- **Alternate assessment:** [CDE CAA ELA/Math](https://www.cde.ca.gov/ta/tg/ca/altassessment.asp) and [CDE CAA Science](https://www.cde.ca.gov/ta/tg/ca/caascience.asp).
- **Student privacy:** [US Department of Education PII guidance](https://studentprivacy.ed.gov/content/personally-identifiable-information-education-records).

These are **starting URLs**, not a declaration that any particular standard or policy has been verified. Recheck exact standard, version, grade, code and source before claiming verification. If inaccessible: `UNVERIFIED — OFFICIAL CHECK REQUIRED`.

## Distinguish four concepts

1. **California state-adopted content standard:** official grade/subject expectation.
2. **Locally prioritized essential standard:** an approved LEA selection, or mark `LOCAL PROPOSED` if assistant-generated.
3. **Core Content Connector:** alternate achievement connector used in the applicable alternate assessment resources; not a local priority standard.
4. **Essential Understanding:** an alternate-assessment resource concept derived from a connector; not a synonym for locally essential content.

Do not automatically assign alternate-assessment participation on the basis of diagnosis or learning profile. That decision belongs to the IEP team and applicable criteria. A functional goal need not be assigned an unrelated academic standard.

## Standards → proposed IEP goal handoff (copyable)

```markdown
# Verified Standards-to-Goal Crosswalk
- Enrolled grade: [ ]
- Subject/domain: [ ]
- Official CA standard ID, grade, short description: [ ]
- Official source URL and access/check date: [ ]
- Source verification status: [VERIFIED OFFICIAL / VERIFIED PROVIDED / UNVERIFIED]
- Approved local priority status: [LOCAL APPROVED / LOCAL PROPOSED / NONE]
- Actual grade-level demand: [ ]
- Prerequisite/enabling skill (INSTRUCTIONAL INTERPRETATION): [ ]
- Educational access/participation connection: [ ]
- Actual student baseline: [from verified intake, never invented]
- Optional verified alternate connector / EU: [only if applicable]
- Suggested progress evidence (NOT an invented target): [ ]
- Items requiring educator/IEP team validation: [ ]
```

An enrolled-grade standard and a distinct individualized prerequisite skill can both matter. Explain the bridge rather than silently replacing the grade-level standard with a lower-grade code.

## Local configuration (fill privately)

```markdown
- AI tool approved for intended data: [YES / NO / UNKNOWN]
- Permitted data category: [synthetic only / de-identified / specifically approved identifiable]
- Local standards/curriculum version and approver: [ ]
- District/SELPA output convention and measurement/reporting rules: [ ]
- Staff who verify standards and approve final IEP content: [ ]
- Retention / disclosure / data-handling policy: [ ]
```

Unknown local rules are **unknown**, never permission to infer a district policy. Store filled student records in an approved private system, **not** the public GitHub repository.

## Use prompts

- **New goal:** "Using the lightweight intake/baseline data provided, draft one measurable annual goal; separate confirmed evidence from proposed targets, mark any missing items, and use the crosswalk only when verified."
- **Audit:** "Evaluate this goal's measurement, baseline comparison, standards relevance, support conditions and progress monitoring; show fixes without inventing data."
- **Progress:** "Compare these real probes with the adopted goal using matching denominators and conditions; explain variability and whether mastery evidence is sufficient."

**Safety:** AI cannot declare compliance, eligibility, services, placement, assessment participation, or final adoption. Use authorized human review.

### Mandatory privacy response contract (v2.2)
For any student-specific material, replace discovered PII in **all assistant outputs** with typed labels, e.g., `[[REDACTED: STUDENT_NAME #001]]`, `[[REDACTED: DATE_OF_BIRTH #001]]`, `[[REDACTED: STUDENT_ID #001]]`. When any marker is used, begin with: **⚠️ PII REDACTED — HUMAN REVIEW REQUIRED. Replace marked information ONLY in the authorized IEP system of record.** At the end list types/tokens only; never show original values or ask users to paste replacements into AI chat. If no PII is detected, say screening is incomplete and indirect identifiers still need manual review. Do **not** assume uploading student-identifiable files to a consumer AI tool is permitted; use approved local pre-upload scanning and qualified human review. Source guide: `docs/PRIVACY_AND_REDACTION.md`.
